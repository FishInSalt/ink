# 搜索工具：grep 与 find

Ink 提供两个只读搜索工具。`grep` 使用 ripgrep 搜索文件内容；`find` 使用
fd 搜索文件和目录名。两者都优先于通过 bash 工具运行 `grep`、`rg` 或
`find`。

## 路径处理

`path` 参数接受相对路径、`~` 家目录路径、`@` 前缀，以及终端和富文本粘贴
常见的 Unicode 空格变体。相对路径返回相对结果路径；`~` 路径返回绝对路径。
路径中的 `link/..` 会先跟随符号链接，再选择其父目录。`~/` 路径也遵循这一规则；
路径末尾有斜杠时，目标必须是目录。

路径不存在时返回一行错误，包含解析后的绝对路径。`grep` 接受文件或目录；
`find` 只接受目录。

## grep

`grep` 以 `path:line:text` 返回匹配行，单文件搜索也会包含文件名。它始终
搜索隐藏的工作区文件，因此 `.github`、`.ink` 和 `.gitignore` 可被搜索，
但会排除 VCS 元数据目录：`.git`、`.svn`、`.hg`、`.bzr`、`.jj` 和 `.sl`。

排除规则作用于递归搜索。如果 `path` 显式指向 `.git` 或其内部文件，
ripgrep 会搜索这个显式目标；需要查看版本库元数据时应有意这样做。未被
`.gitignore` 忽略的隐藏文件（例如 `.env`）仍可能出现在结果中；VCS 排除
不是完整的安全边界。

`grep` 在 Git 仓库内尊重 `.gitignore`。它不读取用户环境中的 ripgrep 配置，
因此结果在不同用户环境下可复现。默认输出限制为前 100 个输出行和 50KB；`limit` 参数可以把行数上限提高到 1000。

## find

`find` 包含隐藏文件，并使用 fd 的常规忽略规则。它在 Git 仓库内尊重
`.gitignore`；在 Git 仓库外，这需要 fd 8.7.0 或更高版本，因为 Ink 会在
那里使用 fd 的 `--no-require-git` 能力。

pattern 是 glob。支持 `src/**/*.ts` 这类带路径的 pattern。开头的 `./` 或
`/` 会被规范化，开头的 `**/` 会匹配任意深度的祖先，因此 `sub/*.ts` 也会
匹配 `a/sub/file.ts`。如果搜索根目录本身名为 `sub`，根级文件也可能匹配。
包含 `..` 段的 pattern 不会被规范化，不在支持的路径 glob 形式内。

`find` 默认返回 1000 条结果，这也是最大值。达到限制时，结果会附带提示，
说明至少找到了这么多条。该提示基于输出行数；文件名包含换行时可能提前
触发。应缩小 pattern 或 path，而不是提高限制。

## 版本与限制

fd 缺少 `--max-results` 能力时会返回清晰的升级错误。较旧 fd 若没有
`--no-require-git`，仍然可用，但不会在 Git 仓库外尊重 `.gitignore`。

两个工具的输出上限都是 50KB。Windows 暂不支持；请使用 WSL。
