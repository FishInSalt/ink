# 会话

当你恢复或分叉一段对话、浏览历史，或者想了解压缩如何工作时，读这篇。模型/提供商
相关问题 → [提供商](providers.md)。

## 会话保存在哪里

会话是以追加方式写入的 JSONL 消息树，保存在 `~/.ink/sessions/` 下，按工作目录
组织。每一轮——用户消息、助手消息、工具调用与结果、模型切换、压缩检查点——都会
保留在磁盘上；内容从不重写。

```bash
ink -c                  # continue the most recent session in this directory
ink -r                  # ink sessions lists them; -r <id> resumes (prefix ok)
ink --no-session        # ephemeral run; nothing persisted
```

在 REPL 中：`/sessions` 列出会话；`/resume <id>` 切换（历史会在屏幕上重放）；
`/new` 开启全新会话（旧会话保留在磁盘上）；`/name <name>` 为会话命名（供选择器
显示）；`/status` 一眼展示会话、模型、上下文和信任状态。退出时总会显示如何恢复：
`ink -r <id>`。

ChatGPT 订阅请求从已有会话 ID 的哈希派生缓存和会话字段：恢复时沿用，
`/new` 时更换。`--no-session` 为每段对话使用一个临时标识，直到 `/new` 才更换。
子会话使用独立标识，重试保持当前标识，摘要不携带标识。

Responses 消息可增加可选的提供商/模型来源与回放元数据，保存最终推理密文、
item ID、文本分段和 phase。JSONL 组织方式和版本不变，旧会话无需重写。
原生元数据只回放给同一提供商的同一模型。其他提供商和摘要只使用普通文本与
工具内容，不接收密文。压缩保留近期消息的元数据，但不将其放入摘要提示。
恢复已选择的订阅模型时，缺少凭据会要求登录，不会静默切换到 API key 计费。

`edit` 的大段插入和删除在模型历史中保留简短成功回执，详细 diff 仅用于显示。

实际通过 `-r`、`-c` 或 `/resume` 恢复时，Ink 只检查末尾 assistant 的工具批次，
以及紧随其后的工具结果。已保存的真实结果保持不变；缺失的结果会追加为明确的
错误记录，说明执行结果未知，工具可能已经全部或部分执行，Ink 没有重跑它。
决定重试前应先检查实际状态。修复在恢复过程中、接收新输入之前完成，即使随后
只是查看会话，也可能已追加修复记录。再次恢复不会重复追加已补齐的结果。

这不是全历史校验：不扫描更早批次或其他分支的工具配对。若未完成批次之后已经
出现新的用户或 assistant 消息，就不属于可修复的末尾形态；应选择完整历史位置
或使用 `/new`，而不是期待自动改写更早的不一致历史。普通用户提交、模型循环、
压缩、历史导航和运行异常不会调用这个主会话恢复函数。原有子会话恢复、普通
工具错误和取消处理保持不变。

恢复会在追加前使用已有的文件末尾残缺记录修复功能。若恢复失败，请重新打开
会话后重试；交互模式会保留原先选中的对话。为避免修改该对话内存存储所引用的
同一文件，若 `/resume` 当前活动会话需要写入修复，会在写入前拒绝：请先 `/new`
再 `/resume <id>`，或重启执行 `ink -r <id>`。无需修复的同会话恢复仍然允许。

## 用量与参考费用

交互状态栏中的 `↑`（普通输入）、`↓`（输出）、`R`（缓存读取）和 `W`（缓存写入）
是整个会话的累计计数，包括所有分支、子代理尝试和摘要。为零的 `R`/`W` 不显示。
`CH` 是按输入 token 加权的累计缓存命中率：`100 × R / (↑ + R + W)`，由原始计数
计算并显示一位小数。它不是最后一条响应的比率，也不是各响应百分比的算术平均值；
输出 token 不参与计算。分母为正而无缓存读取时显示 `CH0.0%`，分母为零时不显示 CH。
压缩以及模型或分支切换不会重置累计值；恢复会话时还原，`/new` 重新开始。
`--no-session` 下不显示这些用量项。比率仅反映已记录用量：未报告的缓存计数按零
参与计算，但缺失用量不会被重建。

参考费用使用产生用量的各提供商和基础模型的当前目录费率；Codex 服务档位调整
归属于原始调用。同一基础模型下按普通/Fast/普通顺序发出的调用保留各自的观测；
改变选择、导航历史、压缩或重新打开会话都不会重新标注此前工作。子代理尝试和
摘要重试的每一步同样保留各自的调用观测，不只使用最后一步的报告。定价绝不会
对原始输入、输出、缓存读取或缓存写入计数乘以倍率。

`~` 表示参考定价不完整，包括未知档位，或旧记录缺少有效观测而按基础费率估算的
Codex 正用量。`!` 仍表示已知存在缺失用量，两种标记相互独立。无效定价元数据
不会破坏有效原始用量。目录费率未知时仍无法定价；估算不能重建未报告的工作用量，
也不衡量实际订阅额度或扣费。规则及固定版本的来源见
[Codex 参考费用估算](providers.md#codex-reference-pricing)。

工具结果的用量统计在 `tool_settled` 或 `tool_end` 观察者收到结果之前捕获。
观察者修改、替换或删除自己的任务记录，不能改变已保存的子代理身份、原始用量或
定价观测；稍后通过保留引用修改也不能改变它们。会话存储在追加消息、保留压缩尾部
以及读取文件时，还会独立复制这些元数据。定价附加信息格式错误时仍保留有效原始
用量；缺失、无效或版本不支持的任务记录仍是未知，不会获得虚构用量。任务元数据
不进入模型输入、摘要或 token 估算。这只隔离用量统计，不冻结工具内容或错误状态，
也不防止宿主代码直接编辑历史或存储条目。已有文件无需重写。

## 模型选择与 Fast

会话保存基础提供商和模型，并为 Codex Fast 选择保存可选的 `speed:"fast"`。
恢复时保留 `·fast`，包括未公开声明能力的自定义模型。已保存的模型没有速度
字段时表示普通模式；恢复它会清除先前的 Fast。旧的、未保存模型的会话仍使用
原有启动优先级，包括显式 `-m ...·fast`。显式 `-m` 与会话保存值之间的既有
优先级不变。`/new` 保留当前模型和速度。无需重写会话或变更版本；仅速度改变
时也会像其他模型选择一样追加记录。

同一基础模型的普通模式与 Fast 共享元数据和兼容的原生回放历史。提供商和
基础模型须精确匹配的回放校验不变；后缀不属于助手消息来源或用量、定价身份。
思考档位与速度独立。

新的 Codex 助手消息还保存可选的 `serviceTier` 观测：
`requested:"omitted"|"priority"`，以及可选、有长度和字符限制的终止响应
`reported` 文本。这些元数据不进入提供商回放、摘要提示或上下文估算，但可按上文
规则调整本地参考费用。没有观测的旧消息仍可读取；费率已知时使用旧 Codex 记录的
仅基础费率估算，并显示定价不完整标记。`/status` 可显示活动历史中与当前提供商和基础模型
精确匹配的 **LAST response**（最后一条响应）；最新助手消息没有有效观测时，不会
替用更旧的记录。这不代表确认当前选择、实际处理档位或计费。有效响应不会仅因
返回档位不同而被拒绝；实际错误和不执行不完整工具批次的规则不变。

每次顶层运行在入口、`run_start` 之前捕获提供商、模型和速度。后续工具调用及
上下文溢出恢复保持该快照；改变 `/model` 影响下一次顶层运行，不影响正在执行
的主循环。新子代理的派发是明确的例外：它在派发时捕获**当前生效的选择**，
而不是父运行之前的快照。子代理继续执行时使用自身记录的速度，而非父级当前
选择。

会话归属与子代理的当前选择分别处理。运行期间通过 `/new` 或 `/resume` 切换
显示的对话时，包括等待自动压缩或上下文溢出摘要期间，该运行接受的检查点、后续
消息和任务记录仍属于它捕获的会话。子代理的父级关联和继续执行查找使用同一个
父会话，而不是替换后的会话；下一次运行才属于替换后的会话。运行开始时没有父级
存储实例的，不会仅因稍后激活了已保存的会话而开始持久保存子代理对话记录。

## 消息树

每个会话的消息构成一棵树，而不是一条线。分叉或跳转会创建分支；活动分支为下一次
模型请求提供历史。

- `/fork`——在较早的某条消息之前分叉对话。从可过滤的用户消息列表中挑选一条，或
  使用 `/fork <n>`。跳到某条用户消息会把它重新放回输入框，以便再次编辑。
- `/tree`——覆盖所有轮次与分支的可视化选择器。方向键移动；Tab 循环切换过滤器
  （default / no-tools / user-only / labeled-only / all）；`f` 折叠子树；`L` 给
  选中条目加标签（标签是可搜索的书签，在任何过滤器下都会保留）；输入文字即
  搜索；Enter 跳转。←/→/PgUp/PgDn 翻页；alt+←/→ 在分支点折叠；ctrl+x 复制选中
  条目的文本；层级较深时自动横向平移。选择器从你当前所在的位置打开。
- 从某个分支跳走时，可以选择把你离开的分支摘要进新位置的上下文（三选一询问：
  No summary / Summarize / 自定义提示词）。`INK_BRANCH_SUMMARY=0` 完全禁用摘要；
  `/settings branchSummary.skipPrompt true` 跳过询问（直接不摘要）。
  `/settings treeFilterMode <mode>` 记住你的默认过滤器。
- readline（非 TUI）shell 把树渲染成带编号的列表；`/tree <n>` 跳到第 n 行。

## 压缩

接近上下文窗口时，较早的轮次会被 LLM 摘要成一个检查点：之后的模型请求使用摘要
加最近的轮次，而完整历史仍保留在磁盘上。`/compact` 手动触发压缩（可选自定义
指令）。`--no-session` 也会禁用自动压缩；`INK_AUTOCOMPACT=0` 或设置中的
`"autoCompact": false` 可将其关闭。`INK_CONTEXT_WINDOW` 覆盖窗口的估算值
（默认 131072）。

Responses 的隐藏推理仅在原生元数据能回放给当前提供商的同一模型时计入上下文
估算。切换模型后不计入该隐藏内容及不兼容的用量测量；切回时，如果内容仍保留，
则重新计入。状态栏、`/status`、自动压缩和近期消息保留范围使用相同的目标模型
估算。密文长度不作为 token 数；切换模型不会改变累计记录用量。

分支摘要（来自 `/tree` 跳转）是另一套机制：它把被放弃的分支记录成单个条目。两者
都会保留原始条目——树从不修剪。

自动压缩和上下文溢出摘要沿用活动运行捕获的速度。手动 `/compact` 和分支摘要
在开始时捕获当前选择；子代理摘要使用子代理自身捕获的速度。摘要重试即使
调整思考档位，也保持相同速度。Fast 出错不会导致按普通速度生成回退摘要。

被接受的摘要在原有检查点或分支摘要条目中携带所有已捕获用量和逐次调用的定价观测。
被拒绝的父会话摘要（例如达到输出上限、为空、失败或中止，或因会话变化而无法安装的
分支摘要）则可追加仅用于用量统计的 `summaryUsage` 回执，保留已捕获的用量及缺失
报告标记。后续重试失败不会丢弃此前步骤的报告。回执绝不包含被拒绝的摘要文本，
也不向上下文或提供商回放提供内容。它不是树节点或导航目标，不改变活动位置，
也不计为用户或助手轮次。

回执属于摘要开始时的会话文件，即使另一会话已变为活动会话。操作期间重新打开
同一文件时，会通过重新打开的存储实例追加唯一一条回执，保持实时与重新打开后
的累计值一致。已安装的摘要只计入被接受的条目；子代理摘要用量只通过子代理的任务
记录计入父级，不额外生成父级回执，也不扫描子代理对话记录。

从未启动的摘要不会被虚构回执或费用估算。工作用量从未报告时仍是未知，不是零费用。
回执写入失败会有诊断，不能据此宣称用量统计已持久保存。已有会话文件无需重写或
变更文件头版本即可继续读取，但含新 `summaryUsage` 条目类型的文件可能无法由
旧版程序使用。

## 多行输入与终端行为

Enter 提交输入。**Shift+Enter** 或 **Ctrl+J** 插入换行；在 Enter 前紧接着输入
反斜杠也是一种换行方式。

在本机 macOS Terminal.app 中，如果终端发送普通回车或 ESC+回车，Ink 会检查
原生 Shift 状态：按住 Shift 时，两种输入都换行；未按 Shift 时，ESC+回车仍保留
Alt+Enter 的行为。这是尽力而为的本机检测，不是修改 macOS 快捷键。通过 SSH
在另一台机器上运行时无法检测本机键盘；必要时改用 Ctrl+J。

Ink 保留普通终端屏幕和原生滚动历史。编辑器使用硬件光标定位输入法候选窗口，
不再同时绘制第二个反色光标。PageUp/PageDown 可在选择器和打开的补全菜单中翻页；
Ctrl+PageUp/Ctrl+PageDown 仍可用于编辑器移动。渲染器不再读取上游的
`PI_HARDWARE_CURSOR` 或 `PI_CLEAR_ON_SHRINK` 默认值；Ink 显式启用硬件光标，
并保持关闭 clear-on-shrink。

渲染宽度错误可能将已渲染的对话文本保存到操作系统临时目录下的私有
`ink-renderer-logs-*` 目录。错误信息会指出文件路径；该目录按需创建，在同一进程内
复用，并保留供诊断。上游 `PI_TUI_DEBUG_REDRAW=1` 日志也使用这个私有目录。
请按对话数据对待这些文件。单独启用的上游诊断选项不会重定向，也不受这个私有
默认目录保护：`PI_TUI_DEBUG=1` 写入上游 `/tmp/tui`，`PI_TUI_WRITE_LOG` 写入
所指定的路径。

Ink 在渲染前和写入诊断日志前检查默认目录的身份与私有权限。如果检测到目录
缺失或不安全，会停止并报错，此时请重启 Ink。对于并发的外部文件系统修改，
这些检查不是原子的；如果已保存文件的权限被外部修改，也无法撤销此前的暴露。

## 转向与后续追问（交互模式）

Ink 工作期间输入的行会排队，绝不丢弃：

- **Enter** → 一条 `steer:` 行，在下一次模型调用前注入正在运行的轮次。默认排空
  模式 `all`：所有排队的转向指令在下一个边界一次性并入。
- **Alt+Enter** → 一条 `follow-up:` 行，在模型本要停下时由同一次运行消费。默认
  `one-at-a-time`：每个回答消费一条后续追问，因此排队的序列会持续前进，无需回到
  空闲状态。
- **Alt+Up / Esc+P** 把所有排队中的行拉回编辑器（保留草稿）；Ctrl+C 中止也会以
  同样的方式交还它们。
- 模式通过设置键配置：`/settings steeringMode` 和 `/settings followUpMode`
  （`all` | `one-at-a-time`）。

终端说明：WezTerm 默认把 Option+Enter 绑成全屏，Alacritty 可能发送普通回车——
把两者都映射为 `\x1b[13;3u`，或改用 Esc+P（出队有回退方案；Alt+Enter 没有）。

## 已知限制

- 已识别但始终未结束的终端响应，可能持续缓冲后续原始按键字节，包括
  Ctrl+C/Ctrl+D。终端完全不回复不支持的查询，并不会因此阻塞输入。后续结束标记
  或新的转义序列可以恢复输入；可尝试先按方向键，再按 Ctrl+C。之前缓冲的按键
  不会重放；单按 Esc 或重复原始 Ctrl+C 并不可靠。操作系统信号仍可绕过此解析器。
  `PI_PROGRAM_STATUS=0` 可选地关闭上游启动状态查询，但不能排除显示内容引发的
  响应或未经请求的终端输入。Ink 不修改上游的这一策略，也不默认关闭查询。
- `/resume` 选择器的输入过滤只消费已提交的文本——输入法组合窗口在组合过程中不
  发出按键（kitty 协议），因此 CJK 输入在提交之后才会参与过滤。粘贴的一块内容
  只取第一行。
